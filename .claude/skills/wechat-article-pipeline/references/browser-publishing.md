# 浏览器读取与公众号草稿保存（WorkBuddy agent-browser）

> 本文件中的「浏览器」一律指 WorkBuddy 浏览器自动化能力（agent-browser skill）提供的已登录浏览器会话。不再依赖 Codex 的 CDP / Chrome DevTools MCP / Playwright。

## 网页读取

### 浏览器选择

优先级：

1. 复用 agent-browser 已登录的浏览器会话（保留登录态与 Cookie）。
2. 通过 agent-browser 新开一个浏览器会话并导航到目标页。
3. 直接 HTTP 获取（仅适用于公开、无动态渲染的页面）。

如果浏览器会话返回空标签页或页面未加载，不要判定网页不可读。用 agent-browser 重新导航到目标 URL 并等待正文节点；没有可用浏览器会话时再回退 HTTP。

### 微信公众号提取

页面加载后等待 #js_content，然后一次返回结构化结果：

    () => {
      const text = (selector) =>
        document.querySelector(selector)?.innerText?.trim() || null;
      const bodyText = document.body?.innerText || "";
      const article = text("#js_content");

      return {
        title:
          text("#activity-name") ||
          document.querySelector('meta[property="og:title"]')?.content ||
          document.title,
        author: text("#js_name"),
        publishedAt: text("#publish_time"),
        content: article,
        contentCharacters: article?.length || 0,
        images: [...document.querySelectorAll("#js_content img")].map((img) => ({
          src: img.getAttribute("data-src") || img.getAttribute("src"),
          alt: img.getAttribute("alt") || ""
        })),
        blocked: /环境异常|访问过于频繁|完成验证|验证码/.test(bodyText)
      };
    }

验证条件：

- blocked 为 false。
- 标题非空。
- 正文节点存在，且长度与页面类型相符；长文章低于 500 字符时人工检查。
- 返回的是文章正文而不是页脚、导航或验证提示。

对通用网页优先使用 article、main、JSON-LD 和 Readability。选择器失败时读取可见正文，不要盲目抓取整个 body。

## 保存草稿前检查

开始外部操作前确认：

- article.md 与 article-wechat.html 存在。
- 标题、摘要和正文已经定稿。
- 不存在未经许可的「待补充」。
- 标题、摘要、正文和图片文案已通过公开内容净化检查，没有来源套话、资料来源区块、原文入口、固定署名、投稿联系方式、模板化互动引导或内部工作流记录。
- 生图能力预检和图片计划已经记录。除非用户明确选择无图，`image_generation.status` 必须为 `complete`。
- 所有计划图片都是真实存在、可解码且像素尺寸有效的本地文件；空白图、灰色占位框、HTML 容器和远程来源图不算最终图片。
- 排版或草稿终点默认具有一张已验证的真实封面；正文图片数量可以为零，但必须与图片计划一致。
- 用户请求包含保存公众号草稿这一终点。

## 浏览器与上传预检

在新建或改写草稿前完成并记录以下检查：

- agent-browser 浏览器会话连接可用，公众号后台已登录，当前账号与目标账号一致。
- 目标封面文件存在、可解码、尺寸有效，并与图片计划一致。
- 浏览器扩展允许访问本地文件，网页文件选择器可以接收目标文件。权限失败时先让用户修复权限，不要在正文写入后才测试。
- 已有 `draft_id` 或 `draft_url` 时能够定位并打开原草稿；不得为了恢复连接另建同标题草稿。

预检只证明环境可用，不代表图片已上传或草稿已保存。将结果和检查时间写入 `wechat_draft.browser_preflight`。

## 后台操作

公众号后台经常更新 DOM。每一步先读取当前页面可见文本、表单角色和可访问名称，再定位元素。优先使用：

1. 可访问名称与角色。
2. 稳定的表单标签和可见文本。
3. 当前 DOM 中确认过的属性。
4. CSS 位置选择器只能作为本次会话的临时方案。

执行顺序：

1. 打开微信公众号后台并确认账号名称。
2. 进入草稿或图文创作入口。
3. 新建或恢复图文草稿，填写标题、作者和摘要。作者默认「吖枫」，只有用户在当次任务中明确指定其他作者时才覆盖；来源文章作者不得自动写入该字段。原文链接等其他字段只在用户明确要求时填写。
4. 填入排版后的正文。
5. 通过上传控件上传封面和正文图片，并确认预览区域出现对应图片。
6. 检查正文中不存在 file:、本地磁盘路径、data:image、失效占位图或用纯色容器模拟的图片。
7. 点击保存草稿。
8. 回到草稿列表或重新打开草稿做回读验证。

修改已有草稿时，先从当前编辑器 DOM 记录文章决定沿用的后台图片标识和线上地址，例如 `data-imgfileid`、`data-src` 或当前 `src`。重建正文时只重新插入确实采用的图片，避免重复上传，也不要把旧草稿里的无关图片带入新文章。

任何一步出现二维码、登录、验证码、风控或账号选择时停止，让用户在同一浏览器中处理后再继续。

浏览器自动化断连或连接中断后，通过 WorkBuddy 浏览器自动化（agent-browser）重新获取浏览器会话并列出当前打开的标签页，再按准确 URL、标题和草稿标识接管原编辑页。旧标签句柄不可继续使用，也不能用猜测的标签 ID 恢复。若原编辑页不存在，使用已记录的 `draft_url` 或从草稿列表打开 `draft_id` 对应条目。

## 保存后验证

至少验证：

- 可见标题编辑器和后台标题字段都与目标标题完全一致；不能只检查隐藏字段。
- 可见作者字段与目标作者完全一致，默认应为「吖枫」；来源作者、账号昵称和公众号作者字段不得混为一谈。
- 正文没有重复渲染标题，摘要与最终正文主题一致。
- 正文字符数与本地文章大致一致；允许平台清洗空白造成小幅差异。
- 保存后重新加载草稿，正文仍包含预期的多个段落或块级节点、章节标题数量、开头锚点和末尾锚点；禁止把单个容器中的扁平文本或只写入前半篇判定为排版成功。
- 关键强调模块和内联样式仍然存在；不能只用正文字数判断排版是否保留。
- 封面预览元素包含 `mmbiz.qpic.cn` 等微信 CDN 地址，并在重新加载后仍然存在。不能因为遮罩层仍显示「拖拽或选择封面」就判定封面缺失，也不能只凭上传成功提示判定持久化完成。
- 正文图片数量一致。
- 正文图片均为后台可访问地址，并可通过稳定图片标识或线上 URL 与预期资源对应；不存在本地路径、临时对象地址或 base64。
- 公开内容净化检查在重新载入后的标题、摘要、正文和图片文案中仍为零命中。
- 页面出现明确的保存成功状态，或草稿列表出现该标题。

确认平台已保存时立即记录保存时间，并可以将 `wechat_draft.saved` 设为 true。标题、作者、摘要、正文结构、正文图片和封面必须分别记录验证结果；只有所有必需分项都通过，才能将 `verified` 设为 true。作者不一致或封面缺失时可保留 `saved: true`，但对应分项与整体 `verified` 必须为 false。

流水线到此只完成「保存到草稿箱」。不要把 `stages.publish: complete` 描述成正式发表。用户后来明确告知文章已发表时，可将 `platform_status` 记为 `published_by_user`，但不得声称该发表动作由流水线完成。

## 安全边界

- 禁止点击群发、发表、定时发表、转载授权或广告投放。
- 不修改账号设置、菜单、自动回复和已有文章。
- 不导出 Cookie、密码、二维码或浏览器存储。
- 账号不一致时停止，不自行选择其他公众号。
- UI 不确定时停在当前页并报告，不通过坐标猜测高风险按钮。
