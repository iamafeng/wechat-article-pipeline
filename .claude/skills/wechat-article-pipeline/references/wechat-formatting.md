# 微信公众号安全排版规范

目标是让文章在微信公众号编辑器中稳定保存、便于扫读并能够可靠回退。内容完整和层级清晰优先于装饰效果。

## 1. 输出模型

- `article.md` 是唯一内容源，`article-wechat.html` 是可重新生成的展示产物。
- 公众号标题字段是标题的唯一展示位置。`article-wechat.html` 不重复渲染文章标题，正文从导读或首个自然段开始。
- 所有视觉样式写在元素的 `style` 属性中，不使用 `<style>`、外链 CSS、脚本或交互。
- 根节点使用 `<section>`。正文优先使用 `section`、`p`、`span`、`strong`、`em`、`blockquote`、`h1` 至 `h3`、`img`、`br`、`hr`、`table`、`tr`、`td`。
- 避免依赖 `<div>`、块级 `<pre>`/`<code>`、`max-width`、`box-shadow`、`overflow:hidden`、复杂 flex/grid 和绝对定位。即使预览正常，也要按微信可能清洗这些结构来设计。
- 链接可能被公众号编辑器改写或移除。正文中保留可读的链接文字，并在发布后验证真正需要的链接。

## 2. 默认主题

默认使用克制的暖陶色主题，可按文章品牌替换强调色，但全文只保留一个主强调色。

| 用途 | 默认值 |
| --- | --- |
| 正文 | `15px`、`#333333`、行高 `1.85` |
| 次要文字 | `13px` 至 `14px`、`#666666` 或 `#999999` |
| 主强调色 | `#C96B3D` |
| 一级标题 | `22px`、粗体、居中、行高 `1.5` |
| 二级标题 | `18px`、粗体、左侧 `4px` 强调色边框 |
| 三级标题 | `16px`、粗体、深灰 |
| 段落间距 | 下边距 `14px`，长段拆分而非增加字号 |
| 模块间距 | 上下 `18px` 至 `24px` |
| 圆角 | `0` 至 `6px`，只用于提示卡、图片和代码块 |

正文不默认使用负字距或随视口缩放的字号。强调色只用于标题边线、关键词、序号和少量标签；普通正文保持深灰。

## 3. 语义模块

根据内容选择模块，不按固定数量堆叠：

- 导读摘要：一至三句，浅色背景加左边框。
- 二级标题：建立长文节奏，不用装饰性大标题重复正文标题。
- 引用：左边框引用只用于确需保留的原话或研究结论；需要公开归属时，在正文语境中自然说明，不生成统一的来源尾注。
- 提示卡：只用于技巧、注意、延伸阅读和风险。一个段落只表达一种提示语义。
- 核心结论：一篇文章最多一至两个，适合可独立截图传播的判断。
- 数据亮点：只展示来源明确的数字，标签必须解释口径。
- 对比：移动端优先上下排列或使用表格，不依赖两栏 flex。
- 分隔与收尾：轻量使用，避免每节都插装饰分隔。

不要嵌套卡片。不要把普通段落包成卡片，也不要让 emoji 成为主要信息载体。

## 4. Markdown 到微信 HTML

转换顺序建议为：围栏代码块、标题、分隔线、引用、列表、独立图片、GFM 表格、普通段落。转换前先转义来源文本中的 `&`、`<`、`>`，再应用允许的行内格式，避免把来源 HTML 当作可信内容注入。

- 段落：连续正文行合并为一个 `<p>`，不同语义段落保留空行。
- 加粗：使用 `<strong>`；强调色只用于关键短语，不染整段。
- 行内代码：可用带浅背景的 `<code>`，但发布后必须回读验证。
- 列表：为提高兼容性，可将每项渲染成独立 `<p>`，前置彩色圆点或数字 `<span>`。
- 表格：使用 `width:100%; border-collapse:collapse` 的 `<table>`，单元格全部内联边框与 padding；列数过多时改写为列表。
- 代码块：使用单列表格承载，代码换行转为 `<br>`，正文先 HTML 转义。不要依赖 `<pre>` 保留空白。
- 图片：使用 `<img>`，`display:block; width:100%; height:auto; margin:16px auto`；本地路径只存在于发布前映射中。

不得用正则解析任意不可信 HTML。现成 Markdown 解析器可用时优先用解析器，再对输出做允许标签与样式收敛；简单、受控的文章子集才可使用轻量转换。

## 5. 配图与图注

- 封面表达文章主题，正文图负责解释概念、流程、关系或数据。
- 图片只呈现读者需要理解的文章内容，不呈现抓取、去重、验证码、浏览器控制、写作、质检、排版或发布过程，除非这些过程本身就是文章主题。
- 正文图前后各保留一个正常段落间距，图注用 `13px` 灰色居中段落。
- 同一篇文章的插图保持色彩、材质、文字层级和宽高逻辑一致。
- 生成前记录生图能力、生成方式（built_in 混元 / agnes）和计划数量。内置生图不可用时停止配图阶段，不创建占位图片；切换到 Agnes 等外部后端必须先获得用户明确同意、且进程能从环境变量读到 `AGNES_API_KEY` 与 `AGNES_BASE_URL`。
- 发布前确认每张图片文件真实存在、可解码且像素尺寸有效，并记录本地路径、目标位置、像素尺寸和文件大小；上传后检查编辑器内实际图片数量和顺序。
- 空白图、灰色占位框、纯色 HTML 容器、远程来源图和无法解码的文件不得计入图片数量，也不得作为封面或正文图交付。
- 不把本地磁盘路径、`file:`、`data:image` 或临时对象 URL 留在最终 HTML。

## 6. 写入公众号编辑器

优先级：

1. 在当前页面寻找可见的 `[contenteditable="true"]`，按可见面积选择最可能的正文编辑器。
2. 回退到本次会话确认过的微信编辑器选择器或可访问角色。
3. 最后检查同源 iframe 内的可编辑正文。

确认目标后聚焦元素，写入 `innerHTML`，依次触发冒泡的 `beforeinput`、`input` 和 `change`。不要使用 `execCommand('insertHTML')`，它可能再次经过粘贴过滤。

若直接写入不可用，才用富文本复制回退：将经过清洗的 HTML 与纯文本 fallback 写入剪贴板，再粘贴到已确认的正文编辑器；不要用键盘自动化的纯文本 `type` 写入整篇文章，也不要优先复制 HTML 源字符串。纯文本输入会让 ProseMirror 将换行合并成单段并丢失章节带、边框和强调样式。任何注入策略都必须先确认当前页面是图文编辑页、账号正确且目标元素是正文编辑器。

富文本粘贴后必须立即回读正文 DOM，至少确认 `p`、`section`、带 `style` 的节点和 `img` 数量均符合本地工件；首段、末段和每个布局锚点的文本也要能被检索。图片先上传到微信后台并将正文中的本地路径替换为后台地址，禁止把 `file:`、`data:image` 或本地路径直接粘贴进编辑器。

静态动感文章如果已经有正文 `h2` 章节标题，不再额外注入章节带或编号块；脚本只统计锚点供质检使用，视觉节奏通过 `h2` 的边框、字号、留白和图片位置完成。额外块级标题会造成微信编辑器中每节出现两个标题。正文图片不要依赖上传控件在当前光标处追加，优先在富文本 HTML 中使用已上传的微信 CDN 地址，粘贴后按前后段落检查图片相邻位置。

修复已有草稿采用“整体覆盖 + 重载复查”，不要在旧正文上追加。覆盖前记录目标章节数；覆盖后和重载后都检查：每个章节恰好一个 `h2`、独立 `01`/`02` 等数字段落为零、图片数量与顺序正确。发现重复块时回到本地 HTML 重新粘贴，不在编辑器中逐块手删，以免留下错位图片或残留样式。

## 7. 发布前后验证

写入后、保存前回读编辑器 DOM，至少抽查：

- 标题层级、段落顺序和正文字符数。
- 二级标题边框、引用背景、强调色是否保留。
- 表格和代码块是否仍是完整行列，没有横向溢出。
- 图片是否已转为后台可访问地址，数量和顺序是否与已验证的图片计划一致；封面是否为真实上传图片而非编辑器占位区域。
- 正文中没有本地路径、base64、脚本、外链样式和未许可占位符。
- 可见标题字段存在且与目标标题完全一致，正文首屏没有重复标题。
- 摘要与最终文章主题一致，不包含来源说明、作者签名、联系信息或工作流记录。
- 公开内容净化检查没有命中不应出现的来源套话、资料来源区块、原文入口、固定署名、投稿联系方式和模板化互动引导。

若样式被清洗，按“内容完整 > 层级清晰 > 装饰效果”的顺序降级：先移除复杂布局，再移除圆角和背景，最后保留纯文本、标题、边框、表格和图片。保存草稿后仍需按 `browser-publishing.md` 再次回读验证。

## 8. 成稿净化与一致性

公开成稿包括公众号标题、摘要、正文 HTML、图片内文字和图注。发布前统一检查这些内容：

- 删除“按照某媒体梳理”“据原文整理”等来源套话，以及资料来源、原文入口一类独立区块。
- 删除固定作者签名、投稿或爆料邮箱、关注账号、点赞转发等与文章主题无关的模板尾注。
- 不把来源 URL、抓取时间、读取方法、浏览器异常、质检记录或发布说明放入公开成稿；这些信息只保留在任务目录中。
- 需要保留归属的直接引语、独家信息或未能独立确认的陈述，应在正文语境中准确归属；不能自然处理时，改用已核验的一手事实、删除该内容或请用户决定。
- 标题、摘要、正文和图片必须围绕同一选题。摘要从最终正文生成，图片只解释正文中的概念、流程、关系、场景或数据。

净化不能以删除必要事实归属或制造原创假象为代价。事实可靠性优先于无来源痕迹。
