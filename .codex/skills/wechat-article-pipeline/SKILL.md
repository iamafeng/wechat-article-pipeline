# 微信公众号文章流水线

把来源读取、原创写作、排版配图和保存草稿串成一次可恢复的任务。保持每个阶段的中间产物，失败时从上一个已验证阶段继续。阶段内部使用可观测状态机；状态定义和完成门见 [references/quality-gates.md](references/quality-gates.md)，浏览器恢复与回退见 [references/browser-recovery.md](references/browser-recovery.md)。

## 运行时兼容（Codex / Claude Code / WorkBuddy）

本 Skill 是**运行时无关**的：核心逻辑只用普通文件与 Node 脚本，不依赖任何单一平台的私有 API。三平台的能力差异按下表映射，运行时按自身具备的能力选择具体实现。

| 能力 | Codex | Claude Code | WorkBuddy |
| --- | --- | --- | --- |
| 项目级技能位置（本仓库已内置） | `.codex/skills/` | `.claude/skills/` | `.workbuddy/skills/` |
| 用户级技能位置（可选） | `~/.codex/skills/` | `~/.claude/skills/` | `~/.workbuddy/skills/` |
| 调用写作技能 | `$<写作技能名>` | 加载指定写作技能 | 加载指定写作技能 |
| 浏览器自动化 | CDP / chrome-devtools MCP | Playwright MCP 或 chrome-devtools MCP | agent-browser skill |
| 内置生图 | 无，走外部后端 | 无，走外部后端或 MCP | 内置 ImageGen（腾讯混元，免费按积分、无 Key） |
| 外部生图后端 | `scripts/generate-image-agnes.mjs`（读环境变量） | 同左 | 同左（需用户当次明确选择） |
| 运行时定义文件 | `agents/openai.yaml` | 不需要 | 不需要 |

详细差异、降级顺序与环境变量见 [references/runtime-compatibility.md](references/runtime-compatibility.md)。下文中的「浏览器自动化」「生图后端」一律按本表映射到当前运行时；**某一能力在当前运行时不可用时，对应阶段标记为 blocked，不得用占位内容冒充完成**。

## 基本原则

- 只保存公众号草稿。绝不点击群发、发表、定时发表或付费推广。
- 公众号作者默认填写「吖枫」；只有用户在当次任务中明确指定其他作者时才覆盖。
- 严格区分「保存到草稿箱」与「正式发表」。用户后续自行发表只作为平台状态记录，不得描述为流水线执行的动作。
- 不编造作者的亲身经历、测试结果、对话、花费或情绪。缺失但关键时标记「待补充」；只有缺失信息会实质改变文章方向时才询问用户。
- 综合来源而不是逐段改写。保留事实出处，避免大段复制原文。
- 严格区分内部证据链与公开成稿。来源、抓取方法、核验记录和操作日志保留在任务产物中，不自动写入标题、摘要、正文或图片。
- 所有正文、排版文件、图片和状态先保存到任务目录，再操作公众号后台。
- 遵守项目的图片安全规则：图片只保存到文件，不在对话中预览；报告路径、尺寸和文件大小。
- 每个阶段先验证再推进。登录、验证码或风控阻塞时停止外部操作，保留本地产物并明确下一步。

## 输入与默认值

接受一个或多个 URL，以及可选的主题、角度、目标读者、个人经历、写作 Skill、输出目录和终点。

- **写作技能可插拔**：通过 `writing_skill` 指定任意写作技能。未指定时按 `references/writing-styles.md` 的默认顺序选择（`khazix-writer` → `writing-style-plain`）。本仓库已内置这两个风格，clone 后开箱可用。Codex 下用 `$<技能名>` 语法，Claude Code 与 WorkBuddy 下加载同名技能。风格的放置规则、默认顺序与新增方法见 references/writing-styles.md。
- 排版主题支持 `basic`（默认）与 `static-motion`。用户选择静态动感时，读取 `references/static-motion.md`，并使用 `scripts/build-static-motion.mjs` 将章节锚点转换为微信兼容的内联 HTML；新文章应通过 `--anchors <json>` 传入本篇的 `{needle,label}` 锚点，避免沿用旧稿默认锚点。
- 未指定公众号作者时使用「吖枫」。文章来源作者只属于来源元数据，不得自动写入公众号作者字段。
- **输出目录已预设**：默认输出到项目根目录下的 `公众号草稿/<YYYY-MM-DD>-<slug>/`（本仓库已提前创建该目录，草稿产物直接落在仓库内）。仍可通过输入参数 `output_dir` 覆盖，例如 `output_dir: 我的草稿/2026-09-14-xxx`。任务目录结构见 references/artifact-contract.md。
- 终点可为素材、成稿、排版或草稿。
- 用户明确要求完整流程或保存草稿时，默认终点为草稿。

启动后创建任务目录并按 references/artifact-contract.md 保存状态。对超过两个来源或需要保存公众号草稿的任务，先给出简短执行计划，然后自主推进。

## 阶段一：读取与解析

逐个读取 URL，不因一个来源失败而丢弃其他来源。

1. 优先使用适合该资源的连接器或网页读取工具。
2. 普通公开页面优先直接获取 HTML 并做 DOM 或 Readability 提取。
3. 微信公众号、动态渲染、登录后内容或直接读取失败时，使用**当前运行时的浏览器自动化能力**打开页面并读取 DOM（Codex 用 CDP / chrome-devtools MCP，Claude Code 用 Playwright 或 chrome-devtools MCP，WorkBuddy 用 agent-browser）。
4. 在浏览器中等待正文节点，必要时滚动触发懒加载，再读取 DOM 文本和图片地址。
5. 检测验证码、环境异常、访问频繁、登录页和空正文。不要把拦截页当作文章。
6. 保存每个来源的元数据、清洗正文、关键事实和来源 URL。

微信公众号优先提取：

- 标题：#activity-name，回退到 meta[property="og:title"]。
- 作者：#js_name。
- 时间：#publish_time。
- 正文：#js_content。
- 图片：优先 data-src，回退到 src。

每个来源至少验证标题、正文长度、拦截状态和最终 URL。详细的浏览器读取规则见 references/browser-publishing.md。

多个来源要生成 source-brief.md，区分共同确认的事实、单一来源陈述、原作者观点、案例和数据、冲突与待核实内容。涉及容易变化的事实、金额、版本、排名、发布日期或争议性陈述时，补充查证可靠的一手来源。

## 阶段二：原创写作

读取并完整遵循用户指定的写作 Skill。未指定时按 `references/writing-styles.md` 的默认顺序确定。不要把写作技能的文风规则复制进本 Skill。

写作前生成 writing-brief.md，至少包含：

- 一句话选题。
- 目标读者和阅读后获得的东西。
- 核心判断与证据。
- 文章原型和叙事推进。
- 可使用的真实个人素材。
- 明确禁止编造的空缺。
- 来源归属与需要引用的位置。

writing-brief.md 中的来源归属只服务于内部核验，不等于公开文章必须附带来源说明。

**写作交接（handoff）**：调用写作技能前，先从 writing-brief.md 抽取一段紧凑的交接块，作为该写作技能的输入前缀，确保关键约束不丢失。交接块至少包含：一句话选题、目标读者与获得感、核心判断与证据、文章原型与叙事推进、可使用的真实个人素材、明确禁止编造的空缺、来源归属与需引用位置、本篇禁用/必用语气。写作技能自带的质检（如 khazix-writer 的四层自检：事实/逻辑/AI腔/行文节奏）应逐项覆盖上述约束；自检结论回填 writing-qa.md，不写进公开成稿。

写作要求：

1. 从来源中提炼新角度，不按原文结构同义改写。
2. 将事实、引用和作者自己的判断分开。需要公开归属的直接引语、独家信息或无法独立确认的陈述，优先改用已核验的一手事实；否则删除或请用户决定，不得通过隐去归属伪装成作者原创。
3. 写作 Skill 要求第一手经历但用户未提供时，使用诚实表述或「待补充个人经历」，不得虚构。
4. 抓取、去重、验证码、浏览器回退、写作 Skill、排版和保存草稿步骤属于内部过程，除非用户明确把工作流本身定为主题，否则不得写进读者正文。
5. 默认从公开成稿中删除来源套话、资料来源区块、原文入口、固定作者签名、投稿或联系信息，以及关注、点赞、转发等模板化引导。只有用户明确要求且确有用途时才保留。
6. 定稿前执行主题纯度检查：逐段确认内容服务于选题，删除工具日志、执行过程、质检结论和面向操作者的说明。对标题、摘要、正文和图片文案执行同一规则。
7. 生成 article.md 后，执行写作 Skill 自带的完整质检并修复问题。
8. 将来源依据和质检结果分别留在 source-brief.md 与 writing-qa.md，不要写进公开成稿。

若文章仍有关键待补充项，可以完成排版预览，但不得保存到公众号草稿箱，除非用户明确要求保留占位符。

## 阶段三：排版与配图

先通读定稿，确定真正需要视觉解释的位置。不要为了数量机械插图。

排版前完整读取 references/wechat-formatting.md，并以其中的微信安全 HTML、主题参数、模块选择、成稿净化和降级规则为准。

先执行生图能力预检，并按当前运行时选定生图后端：

- **后端优先级**
  1. 运行时内置生图：WorkBuddy 的 ImageGen（腾讯混元 HY-Image，免费、按积分计费、无需 API Key）存在时默认使用。
  2. 外部 OpenAI 兼容后端：调用 `scripts/generate-image-agnes.mjs`，读取环境变量 `AGNES_API_KEY`（缺失则标记 blocked）与 `AGNES_BASE_URL`（未设置时用默认网关 `https://apihub.agnes-ai.com/v1`），默认模型 `agnes-image-2.0-flash`。Codex 与 Claude Code 无内置生图，这条即默认外部后端。
  3. 以上都不可用时，保留文章与 PROMPTS.md，将配图阶段标记为 blocked，不得用空白图、灰色占位框或来源图片冒充生成完成。
- **切换门禁**：WorkBuddy 下从内置切到 Agnes 必须同时满足 (a) 用户在当次任务中明确选择 Agnes 后端；(b) 环境变量 `AGNES_API_KEY` 存在。Codex / Claude Code 下 Agnes 为默认外部后端，但仍要求 `AGNES_API_KEY` 存在，缺失则标记 blocked。**绝不静默走任何外部计费路径**。
- 预检结果（后端、是否可用）写入 workflow-state.json 的 `image_generation.capability` 与 `image_generation.backend`。

生图与验收：

1. 封面、场景图或其他位图使用选定的生图后端：
   - 内置 ImageGen：直接调用 WorkBuddy 内置 ImageGen（文生图）工具。
   - Agnes 后端：调用 `scripts/generate-image-agnes.mjs --prompt "<提示词>" --out "<assets/xxx.png>" --size "<宽x高>" [--model "<模型名>"]`；脚本将图片写入任务目录 assets/ 并输出 JSON 结果（path、bytes、width、height、model）。任何失败都标记为 blocked，不得用占位图冒充。
2. 概念、流程、系统关系和数据图可先由配图规划技能规划视觉结构（可选技能，需另行安装；未安装时直接用所选后端生成）。要求文字精确的架构图/流程图优先用确定性渲染（如 Mermaid/SVG），避免 AI 生图文字出错。
3. 排版或草稿终点默认生成一张真实封面；正文配图按内容需要规划为 0 至 4 张。遇到流程、系统关系、数据/对比、可复用步骤，或长文超过约 2500 字且章节间缺少视觉停顿时，优先增加正文图；纯观点或短叙事不机械插图。
4. 图片提示词、采用版本、生成方式、尺寸、文件大小和路径写入 PROMPTS.md 与任务清单。
5. 每张最终图片必须保存到任务目录 assets/，且文件存在、可解码、像素尺寸有效；只有通过这些检查的文件才能计入 image_count。生成脚本解析自身目录必须使用 Node `fileURLToPath(import.meta.url)`，不得直接使用 `new URL(...).pathname`，避免中文目录被 `%E5...` 编码导致写文件失败。
6. 视觉检查必须验证文字、裁切、主体、数据、水印和多图风格一致性；封面还要与近期文章候选做 SHA-256 去重并完成人工构图/主色差异检查。只报告文件，不在对话中展示图片。
7. 配图必须直接服务文章主题，不得出现抓取、浏览器控制、排版、质检、保存草稿等生产过程，除非文章主题就是该工作流。
8. 计划中的任一图片未生成或未通过检查时，配图阶段不得标记为 complete。

**封面专项**：封面是公众号点击率的关键，单独提质要求：

- 封面优先用更高质量档（ImageGen 的 `quality: high`，或 Agnes 后端的高分辨率模型）。中文标题/活动类封面可优先选用中文场景更强的即梦（jimeng）等后端生成后导入 assets/，但必须在 PROMPTS.md 记录来源与模型。
- 封面必须表达文章核心主题，避免抽象装饰；与近期文章封面做 SHA-256 去重，确保构图、主体、主色有明显差异。
- 封面与正文图保持同一视觉家族（色彩、材质、文字层级、宽高逻辑一致）。
- 封面文件须通过解码与像素尺寸检查，并在上传后回读微信 CDN 地址验证持久化；未持久化不得标记 complete。

生成 article-wechat.html：

- 使用简单、可被公众号编辑器保留的内联样式；以 section、p、span、strong、blockquote、h1 至 h3、img 和 table 为主要结构。
- 标题只写入公众号标题字段，不重复放进正文 HTML；正文从导读或首个自然段开始。
- 以短段落和充足留白为主，不改变写作 Skill 的正文节奏。
- `static-motion` 只借鉴 HyperFrames 的视觉节奏与静态构图，不把 GSAP、脚本、iframe、CSS 动画或复杂交互写入公众号正文；动感通过章节带、结论卡、方向性元素、图片比例和留白实现。
- 不使用脚本、外链 CSS、max-width 容器、阴影、复杂布局、表单或交互元素。
- 代码块和需要严格对齐的数据使用内联样式的 table 降级，不依赖块级 pre/code；普通列表优先渲染为稳定的段落列表。
- 模块化卡片只用于导读、引用、提示、核心结论、数据和收尾等真正有语义的内容，全文保持一种主强调色。
- 图片位置使用明确的本地文件映射，写入公众号后台时替换为上传后的图片。
- 同时保留 article.md 作为内容源，HTML 只负责展示。
- 摘要从最终文章主题生成，并执行与正文相同的公开内容净化。

排版后检查标题、正文顺序、链接、强调、引用、表格、代码块、图片顺序、图片说明和移动端可读性，并记录所用主题与模块清单。

## 阶段四：保存公众号草稿

仅在用户请求终点为草稿，且文章不存在未获许可的关键占位符时执行。

1. 优先使用**当前运行时的浏览器自动化能力**复用已登录的浏览器会话，进入微信公众号后台（Codex 用 CDP / chrome-devtools MCP，Claude Code 用 Playwright 或 chrome-devtools MCP，WorkBuddy 用 agent-browser）。
2. 写入任何公开字段前完成后台预检：浏览器连接正常、公众号已登录、账号正确、封面文件有效、本地文件上传权限可用。预检结果写入 workflow-state.json；上传权限失败时不要创建或改写半成品草稿。
3. 登录失效、需要扫码或验证码时，停下并请用户完成登录；不要尝试绕过验证。
4. 新建或恢复图文草稿，填写标题、作者、摘要、正文和封面。作者默认「吖枫」；用户当次明确指定其他作者时使用指定值。原文链接及其他署名信息仅在用户明确要求时填写。
5. 正文写入必须保留块级结构。优先使用编辑器支持的富文本 HTML 粘贴，或通过编辑器自身事务写入并触发 beforeinput、input、change 事件；禁止用逐字 `type` 把整篇正文当纯文本写入，因为这会把换行、章节带和内联样式压平成一个段落。富文本粘贴后必须回读 `p/section/img` 等块级节点，再保存。
6. 通过页面提供的上传控件上传本地图片。修改已有草稿时，先记录需要沿用的后台图片标识或线上地址，只把文章实际采用的图片重新插入。封面替换必须使用新文件名，并分别记录 uploaded、applied、persisted；不要把本地路径、临时对象地址或 base64 留在正文中。
7. 保存前回读可见标题、作者、摘要和正文 DOM。正文必须同时通过块级节点、预期章节数量、开头锚点和末尾锚点检查；至少确认段落数大于 1、章节带数量符合预期、正文图片数量符合清单、首尾锚点存在；不能只以有文字或字符数接近判定成功。公开内容净化也必须为零命中。
   - 修复已有草稿时先整体覆盖为最新 HTML，再做检查；每个章节只允许一个语义标题。已有 `h2` 时，不得同时保留同章节的纯数字段落（如 `01`、`02`）或重复章节带。
8. 保存到草稿箱，不点击任何发表或群发动作。保存后重新加载同一草稿，并回到草稿列表确认列表卡片封面 CDN 地址非空；单次编辑器预览或保存提示不能代替该验证。
9. 记录明确的保存成功状态和时间，然后重新加载同一草稿，分别回读验证标题、作者、摘要、正文结构、正文图片、封面和保存状态。正文结构验证必须在重载后再次执行，确认段落没有重新扁平化；封面以预览元素中的微信 CDN 地址为准，不能根据「拖拽或选择封面」等遮罩文字判断。重载后的最终门禁是：`h2` 数量等于预期章节数，独立数字标题段落数量为 0，正文图片数量、顺序和首尾锚点与本地清单一致；任一不符时标记 `needs_browser_reapply`，不得报告为已验证。
10. 将草稿标识、编辑 URL、保存时间、分项验证结果和验证时间记录到 workflow-state.json。作者不一致、正文扁平或末尾缺失、封面未持久化时，可以记录已保存，但不得把整个草稿标记为已验证。
11. 用户后来告知文章已经正式发表时，只将 `platform_status` 更新为 `published_by_user` 并记录报告时间，不修改流水线保存与验证结果。

不要依赖永久 CSS 选择器。公众号后台 UI 变化时先检查当前 DOM、可见文本和可访问名称，再操作。浏览器断连后重新获取浏览器会话与当前标签页；已有草稿标识或编辑 URL 时必须恢复原草稿，禁止误建重复草稿。详细规则与失败恢复见 references/browser-publishing.md。

## 完成标准

只有目标终点对应的所有条件满足，才声明完成。可用 `scripts/validate-cover.mjs` 检查图片身份，用 `scripts/validate-wechat-artifact.mjs` 检查文章和 HTML；脚本输出与后台重载证据必须写入任务状态：

- 素材：全部可读来源已解析，失败来源及原因已记录。
- 成稿：文章和写作质检均已生成，不含未经许可的关键占位符，公开内容净化检查为零命中。
- 排版：HTML、真实图片和资源映射完整，文件均可读取并通过图片解码与尺寸检查；标题未在正文重复，图片均服务文章主题。用户明确选择无图时除外。
- 草稿：公众号后台显示已保存，标题、作者、摘要、正文、正文图片和封面均完成重新载入后的分项验证；正文具有预期块级结构与首尾锚点，没有用占位元素冒充图片，也没有触发发表或群发。

最终简洁报告任务目录、文章标题、来源成功或失败数、正文字符数、图片数量、公众号草稿状态，以及仍需人工处理的事项。

## 运行时兼容说明

本 Skill 为跨运行时设计，同一份文件在 Codex、Claude Code、WorkBuddy 下均可运行，差异只在能力映射：

- **写作技能可插拔（内置两个风格）**：流水线不绑定单一风格，通过 `writing_skill` 参数指定。仓库已内置 `khazix-writer`（人格化长文，MIT，版权归数字生命卡兹克，该目录内附 LICENSE 原件）与 `writing-style-plain`（中性干净直白，本仓库自研）。未指定时按 `references/writing-styles.md` 的默认顺序选择，因此 clone 后开箱即可写作。Codex 下用 `$<技能名>` 引用，Claude Code 与 WorkBuddy 下加载同名技能。任何能接受「写作交接块」的技能都可接入，新增方法见 references/writing-styles.md。
- **生图后端可插拔**：WorkBuddy 有内置 ImageGen（腾讯混元，免费按积分、无需 Key），默认使用。Codex 与 Claude Code 无内置生图，使用 `scripts/generate-image-agnes.mjs` 走 OpenAI 兼容外部后端（默认网关 `https://apihub.agnes-ai.com/v1`，默认模型 `agnes-image-2.0-flash`，密钥从环境变量 `AGNES_API_KEY` 读取，不硬编码）。WorkBuddy 下切换到 Agnes 需用户当次明确选择且环境变量存在；任一不满足即退回内置或标记 blocked，**绝不静默走外部计费路径**。
- **配图规划（可选）**：配图规划技能用于概念/流程/数据图的视觉结构规划，需另行安装；未安装时直接用所选后端生成。要求文字精确的架构/流程图建议改用确定性渲染（Mermaid/SVG）。
- **封面专项**：封面优先高质量档，中文标题封面可优先即梦（jimeng）等中文场景更强的后端；封面与近期文章做 SHA-256 去重与构图/主色差异检查。
- **浏览器能力按运行时映射**：读取来源与保存草稿的浏览器操作，在 Codex 下走 CDP / chrome-devtools MCP，Claude Code 下走 Playwright 或 chrome-devtools MCP，WorkBuddy 下走 agent-browser。见 references/browser-publishing.md、browser-recovery.md、runtime-compatibility.md。
- **输出目录已预设**：默认 `公众号草稿/<YYYY-MM-DD>-<slug>/`（仓库根目录，已提前创建），支持通过 `output_dir` 覆盖；该目录已加入 .gitignore，草稿产物留在本地、不随仓库推送。
- **Codex 运行时文件**：`agents/openai.yaml` 为 Codex/OpenAI Agents 运行时定义，仅 Codex 读取；Claude Code 与 WorkBuddy 忽略该文件，不影响运行。
- **脚本兼容性**：`scripts/*.mjs` 为纯 Node 脚本（Node 18+），三平台通用；保持 `fileURLToPath(import.meta.url)` 解析目录，避免中文路径编码问题。
